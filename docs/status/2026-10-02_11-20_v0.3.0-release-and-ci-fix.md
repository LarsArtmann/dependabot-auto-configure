## e) WHAT WE SHOULD IMPROVE

1. **Release notes have two sources of truth.** The GitHub Release body and the CHANGELOG section say the same thing in different words and will drift. Fix: generate the release body from the `[X.Y.Z]` CHANGELOG section (script or workflow), keeping the curated highlights as a short lead-in inside the CHANGELOG itself.

2. **The release process lives in my head plus the skill.** Every step (gates, tag message, proxy verification, release creation) was manual this session. Fix: add `.github/workflows/release.yml` (on `v*` tag: create the GitHub Release from the CHANGELOG section) and a `scripts/pre-release-check.sh` wired to THIS repo's gates (the skill ships a generic one; this repo's gate list in AGENTS.md is the real one).

3. **Pre-flight "is master green?" should be step 0.** One `gh run list` before any gate saves a mid-release CI fix. Fix: put it at the top of the release runbook/script and make the script refuse to start on a red branch.

4. **Post-push verification is a URL-fetching ritual.** I fetched proxy `.info`, ran clean-dir `go get`, and probed pkg.go.dev by hand. Fix: codify as `scripts/post-release-verify.sh <version>` (proxy .info, sum DB, clean-dir go get, pkg.go.dev fetch with retry/backoff).

5. **Windows skips accumulate silently.** This is now the first Windows-skipped test in the suite. Fix: keep a documented list (AGENTS.md Testing section) of every Windows-skip with its reason, and prefer ACL-based exercise-over-skip where feasible.

6. **Environment integrity checks after weirdness.** The tag deletion should have triggered a `git fsck` + reflog review immediately, not just a restore. Fix: when git state contradicts known history, investigate before patching over it.
